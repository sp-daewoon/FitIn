# Current handoff

## Implemented state

Private repository: `sp-daewoon/FitIn`, main. Source/web remain development 0.0.2; `v0.0.1` and `web/v0.0.1` are immutable historical previews. PPL/catalog expansion was already part of the 0.0.1 baseline; the former handoff incorrectly described it as post-baseline. Claude's persistent builder is commit `124c598`; the current changes build on it without discarding saved templates.

- Seven program choices now live in “내 루틴”. Today / next visit / visit after use the shared resolver. Program switching keeps templates and personal starters. Legacy difficulty fields remain readable but the nonfunctional selector is hidden.
- Recommended plans use five distinct exercises × five editable 60-second work windows = 25 planned work minutes, excluding rest. Total with default rest/transitions is 59:10. Shorter custom goals remain valid. The target is a user-requested UI planning convention, not an evidence-based minimum or measured exercise time.
- The user confirmed on 2026-09-12 that forty minutes is the default starter configuration, not a cap: adding exercises simply makes the session longer. The `capPlan` truncation helper and its test were removed so no code path can reapply the old policy, and the superseded clauses in the [builder brief](releases/post-0.0.1-routine-builder.md) and [0.0.2 note](releases/0.0.2.md) now say so explicitly. New sessions run the whole plan including finishers without a 40-minute cutoff. Existing v2/v3 sessions retain their original cap. `fitin.v4` migration preserves originals, paused state, phase IDs, global rest and templates. `defaultPlan` keeps older short examples for legacy tests; `recommendedPlan` is the current generated recommendation. `resolvePlan` owns actual preview/execution selection.
- The persistent builder supports add/remove/reorder, multiple finishers, global rest and explicit per-exercise overrides. Today's changes affect future visits only through explicit save. Duplicate movements require the finisher flag and distinct indexed phase IDs.
- Watch preview uses exercise imagery beneath text/time, with shared phone commands. It is explicitly disconnected; no native Watch target exists yet.
- Native iOS generation uses `app.config.js` and independent platform versions. The local-notifications plugin removes the unused APNs entitlement so a personal Apple development team can sign. Keep it before expo-notifications because entitlement mods execute in reverse registration order. Local reminders require no APNs capability.
- The catalog has 22 draft-illustrated exercises and video references/search fallback. Images remain unreviewed anatomically. HealthKit and native AirPods controls are still planned, with truthful disconnected UI.
- Session clock policy (FIT-020): the display tick now runs only while a session is advancing, which fixes the sluggish taps caused by re-rendering the whole screen ten times a second on every tab. Sessions carry a `lastSeen` heartbeat, and `reconcileOnLaunch` runs on cold start only, so a screen-off period still counts while a gap after process death is frozen out, paused and put to the user as a question. `resumeAfterGap` applies their answer. The field is additive: snapshots saved without it fall back to the last anchor, so no storage version bump was needed.
- Record deletion (FIT-021): the history tab deletes one record or all of them behind a confirmation that names the consequence. `removeRecords`/`clearHistory` leave an active session and saved templates alone, and the routine cycle is recomputed from what remains rather than rewritten to look continuous.
- Bundle identifier decision: `com.spdaewoon.fitin` stays for now. The user chose to keep it through development and pick the final identifier just before store registration, because changing it orphans the records already on the phone and forces another prebuild and signing round. Revisit before any public distribution; the personal handle must not ship.
- Routine editing (FIT-018, FIT-022): the finisher concept is gone. Adding an exercise is one control, and an explicit "이미 넣은 운동도 다시 추가" checkbox allows a deliberate repeat; validation no longer rejects duplicates, and a test asserts that every generated default plan is still unique. Work duration steps by 5 seconds, rest by 15. Visit cards now follow the cycle length, so a two-visit split shows no 다다음 방문. A new `custom` split lets the user pick up to three visits and what each one is, stored in `preferences.customCycle` as an optional additive field. Switching program styles keeps saved templates and returns to the top of 내 루틴 instead of jumping to 오늘의 운동.
- Consequence of dropping finishers: a movement the user appended is no longer distinguishable from a generated one, so a starter preference can choose it for substitution. That substitution is still reported to the user and never changes the session length, but the old end-of-session protection is gone. The starter feature is largely superseded by the builder; revisit or remove it rather than adding new protection logic.
- Layout stability: `ExerciseVisual` no longer measures itself with `onLayout` and re-renders at the measured width. It reserves a square through `aspectRatio` and positions the atlas cell in percentages, which removes the first-paint jump the user reported when checking in.
