# FitIn 0.0.2 · persistent routine builder (development, not released)

Status: **development**. No tag is published for this version and no platform artifact exists. The immutable preview baseline is still [0.0.1](0.0.1.md) (`v0.0.1`, `web/v0.0.1`); those tags are unchanged.

## Scope

Implements [FIT-018](../requirements.json) from the [routine builder brief](post-0.0.1-routine-builder.md):

- `내 루틴` is a persistent goal template stored per routine. `오늘의 운동` is a one-day copy that never writes the template unless the user presses `내 기본 루틴에도 저장`.
- One global rest control, default 90 seconds, selectable 45–180. It reaches every set except an exercise whose rest was explicitly overridden. A rest value edited by hand, or inherited from a version-2 saved plan, is marked and labeled as an override so a later global change cannot discard it silently.
- Per-exercise work duration, default 60 seconds, adjustable 20–180, in both the template builder and today's copy.
- Add, remove and reorder exercises inline. Explicit finishers are appended at the end and may repeat a movement; default sequences stay unique. The item cap moved from 8 to 12.
- Timing breakdown separates exercise time, rest, transitions and setup, and states the remaining or over-cap amount.
- A template may exceed 40 minutes. Check-in then requires a choice: run to the cap with the named remaining items recorded as unperformed, or shorten today's copy. Rest is never compressed and no item disappears silently.
- The routine page leads with compact 오늘 / 다음 방문 / 다다음 방문 cards; long guidance moved behind one `자세히` toggle.

## Storage

Local data moves to `fitin.v3` (`preferences.globalRest`, `preferences.templates`). A `fitin.v2` snapshot still decodes and is upgraded in memory only; the v2 key is never rewritten or cleared, and explicit v2 saved-plan rest values are preserved rather than overwritten by global rest.

## Validation

TypeScript, 50 tests (9 new builder/migration cases), harness consistency check and `expo export --platform web` passed on 2026-09-12 with Node 22. Prettier reported no changes.

## Known limitations

Not device tested. No phone or browser visual QA, no native build, no Watch, AirPods or HealthKit verification. Generated exercise anatomy remains draft. `npm run release:check` still fails on the seven unverified readiness gates and the draft atlas, so this version is not releasable and must not be tagged or published as a preview until those gates are addressed.
